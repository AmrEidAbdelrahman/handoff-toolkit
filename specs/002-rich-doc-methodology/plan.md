# Implementation Plan: Rich Documentation Methodology — Diagrams & Business Documents

**Branch**: `002-rich-doc-methodology` | **Date**: 2026-05-29 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/002-rich-doc-methodology/spec.md`

**Depends on**: Feature 001 (Handoff Platform) — toolkit and extension established there are the foundation this feature extends.

---

## Summary

This feature adds two layers of richness to the Handoff output format. Phase 1 extends the toolkit: the agent follows a defined diagram decision matrix to embed Mermaid diagrams into nodes, and recognises structured document opportunities (ADRs, runbooks, onboarding guides, API summaries) to produce as typed business documents alongside standard handover nodes. Phase 2 extends the VS Code extension: it renders diagrams visually using a bundled Mermaid browser build, applies document-type-aware layouts (card for ADRs, checklist for runbooks, reading sequence for onboarding guides), and wires diagram elements to code navigation via `code_refs[].id` matching. All schema changes are additive and backward-compatible — existing 001 output requires no migration.

- Diagram rendering completes within 300ms of panel open (Mermaid SVG generation is synchronous in webview)

**Constraints**:
- Offline required — Mermaid renderer MUST be bundled; no CDN or external calls
- `schema_version` remains `1` — all new frontmatter fields are optional and additive

## Phase 1: Toolkit

### Deliverables

**1. New `diagram-methodology.md` rule file** (`.handoff/toolkit/rules/diagram-methodology.md`):

- Diagram decision matrix table (normative) — section category → required/optional diagram types
- Diagram format: Mermaid only; all four supported types: `flowchart`, `flowchart LR`, `sequenceDiagram`, `erDiagram`
- Diagram validation step: agent calls a self-check pass on generated Mermaid source; if syntax error detected, attempt one correction; if still invalid, replace with prose
- Naming convention for `code_refs[].id`: lowercase, hyphenated, derived from module/class name; unique within node
- Business document catalogue: templates for ADR, Runbook, Onboarding Guide, API Summary with required/optional sections
- Detection signals per document type:
  - ADR: architectural comments (`# Architecture Decision:`, unusual patterns, commit messages with "decided" / "chose" / "rejected")
  - Runbook: startup scripts, deployment configs, CLI entrypoints, files named `*deploy*`, `*start*`, `Makefile`
  - Onboarding Guide: always produced at session end
  - API Summary: presence of `openapi.yaml`, `schema.graphql`, `swagger.json`, or equivalent

**2. Updated `handoff-start/SKILL.md`** — adds two new phases to the existing 7-part instruction:

- *Phase 2b (after per-section scan)*: Classify each section against the diagram decision matrix. For required diagram types, draft diagram source. For optional types, check code evidence before drafting. Assign `code_refs[].id` to refs that should be navigable from diagrams.
- *Phase 2c (during/after section drafting)*: Evaluate each section for business document opportunities using detection signals. Draft applicable documents (ADR, Runbook). After all sections complete, draft the Onboarding Guide (always).
- *Phase 5b (during node save)*: Validate all diagram source blocks; correct or replace as needed. Set `diagram_format: mermaid` in frontmatter if any diagrams passed validation.
- *Phase 5c (during node save)*: Set `doc_type`, `doc_refs` on all business document nodes. Add `doc_refs` to linking handover nodes.

**3. Updated `output-schema.md`** — append rules OP-06 through OP-12:
- OP-06: `doc_type` optional; valid values; absence = `handover_node`
- OP-07: `diagram_format` present iff `## Diagrams` section exists
- OP-08: Each diagram block must have H3 title, description line, fenced mermaid block
- OP-09: `doc_refs` entries must resolve to existing files in `nodes/`
- OP-10: `code_refs[].id` format rule; uniqueness within node
- OP-11: Diagram element labels intended for navigation must match `code_refs[].id` exactly
- OP-12: Document-type-specific body section requirements (ADR/Runbook/Onboarding/API body rules)

### Phase 1 Gate

Run `/handoff-start` on this repository. Verify:
- At least one node contains a `## Diagrams` section with valid Mermaid source and `diagram_format: mermaid` in frontmatter
- An `onboarding-guide.md` node exists with `doc_type: onboarding_guide` and a non-empty reading order
- All produced nodes pass `/handoff-validate`

## Phase 2: VS Code Extension

### Deliverables

**1. Updated `nodeReader.ts`**:
- Parse `doc_type` frontmatter field (default: `'handover_node'`)
- Parse `diagram_format` frontmatter field
- Parse `doc_refs` frontmatter field
- Extract `## Diagrams` section: parse each diagram block into `ParsedDiagram[]` (title, description, source)
- Parse `code_refs[].id` optional field

**2. Updated `treeProvider.ts`**:
- Map `doc_type` to icon: `handover_node` → existing icon; `adr` → scales icon; `runbook` → checklist icon; `onboarding_guide` → map icon; `api_summary` → network icon
- Unknown `doc_type` values fall back to default icon without error

**3. New `mermaidRenderer.ts`**:
- Builds the webview HTML scaffold that loads `mermaid.min.js` from `dist/assets/`
- Exposes a `renderDiagrams(diagrams: ParsedDiagram[], codeRefs: CodeReference[])` function
- After rendering: queries SVG label elements, matches text to `code_refs[].id`, injects `data-id` attribute, registers click handlers via `postMessage` bridge (same pattern as code-ref navigation in 001)
- Fallback: if Mermaid throws, display raw source in `<pre>` block

**4. Updated `webviewPanel.ts`**:
- Dispatches rendering based on `node.docType`:
  - `adr`: structured card layout (Context / Decision / Consequences sections with border + tint, `adr_status` badge)
  - `runbook`: numbered step list with per-step checkbox; checkbox state via `workspaceState` keyed `handoff.runbookProgress.<nodeId>.<stepIndex>`; on click → toggle state + re-render
  - `onboarding_guide`: project summary prose, numbered reading order as clickable links (postMessage → open node), related documents as links
  - `api_summary`: two-column table for Endpoints / Operations section
  - `handover_node`: existing prose layout + diagram section appended at end (calls `mermaidRenderer`)
- Diagram section for `handover_node`: iterates `node.diagrams[]`, delegates each to `mermaidRenderer`

**5. Bundled `mermaid.min.js`**:
- Add `mermaid` to `package.json` devDependencies
- Add build script step: `cp node_modules/mermaid/dist/mermaid.min.js dist/assets/mermaid.min.js`
- Reference in webview HTML via `webview.asWebviewUri()`

### Phase 2 Gate

End-to-end test using Handoff dogfood output:
- Open workspace in VS Code → sidebar shows distinct icon for onboarding guide node
- Open onboarding guide → reading order renders as clickable numbered list
- Open a diagram-containing node → diagram renders as SVG (not raw text)
- Click a navigable diagram element (one with matching `code_refs[].id`) → VS Code opens the referenced file at the correct line
- Open an ADR node → structured card layout visible (not prose)
- All tests pass offline (no network)
