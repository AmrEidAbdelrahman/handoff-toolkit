# Handoff Toolkit Output Contract — v4.0

**Supersedes**: v3.0 (feature 003)
**Date**: 2026-05-31
**Backward compatible with**: v2.0, v3.0

---

## New Rules (feature 004)

**O-09**: Every generated node MUST contain a `quality_score` frontmatter field after Part 5d completes. All dimension values in `quality_score` MUST be `1` or `2` — the value `0` MUST NOT appear in a saved node (0 triggers rewrite before save).

**O-10**: Every sentence in `## Business Context`, `## Decisions`, and `## Warnings` sections that was AI-inferred MUST end with a `(src: <identifier>)` citation. Identifiers must follow the four-format convention (README §, file:line, commit sha7, or `inferred`). Fabricated identifiers are not permitted.

**O-11**: Every node MUST contain a `confidence_tags` frontmatter field for each field appearing in `inferred_fields`. Values must be exactly `high`, `medium`, or `low`. When a giver confirms a field, its entry is removed from both `inferred_fields` and `confidence_tags`.

---

## Inherited Rules (v3.0, unchanged)

**O-01**: Every generated node MUST have valid frontmatter (FM-01 through FM-08 pass).

**O-02**: Every generated node MUST have a `## Business Context` section with at least one non-empty paragraph.

**O-03**: Every generated node MUST have a `## Technical Context` section with at least one non-empty paragraph.

**O-04**: For `handover_node` documents, section order is fixed: Business Context → Technical Context → Decisions (optional) → Warnings (optional) → Diagrams (optional).

**O-05**: `code_refs` is optional. Nodes generated by `/handoff-start` from feature 003 onwards MUST NOT include `code_refs`.

**O-06**: The output index MUST list `architecture-overview` as position 0.

**O-07**: Domain node titles MUST be in plain English business language — no raw directory path components.

**O-08**: The output directory MUST include an `index.md` file with a `## Business Overview` section first and a `## Domain Reference` section second.

---

## Breaking Changes from v3.0

None. O-09 through O-11 are new requirements on nodes generated by `/handoff-start` from feature 004 onwards. Nodes generated before feature 004 that lack `quality_score` and `confidence_tags` remain valid under the validation schema (both fields are schema-optional per OP-14/OP-15).
