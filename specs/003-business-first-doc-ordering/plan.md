## Phase 3 — handoff-start SKILL.md Rewrite

**Goal**: Reorder generation (business docs first), add semantic domain discovery, replace code_refs with inline snippets, add architecture overview node, add index.md generation.

**Deliverable**: Updated `.handoff/toolkit/skills/handoff-start/SKILL.md`

### 3.1 — Part 2: Semantic Domain Discovery (replaces directory-based Step 2.2)

**Change Step 2.2** ("Identify logical sections") to "Identify business domains" using this logic:

1. **Signal 1 — README**: Scan for section headings and feature descriptions. Extract named capabilities.
2. **Signal 2 — Framework app boundaries**: For each top-level directory with an `__init__.py` / `index.*` / `mod.rs` / `package.json`, treat it as a domain candidate. Read `models.py` or `models/` to understand what business entities it manages.
3. **Signal 3 — Route/URL registrations**: Look for `urls.py`, `routes.*`, `router.*`. Group routes into the domains they belong to.
4. **Signal 4 — Import topology**: Count how many other directories import from each directory. Directories imported by 3+ others are infrastructure candidates (cross-cutting), not domains.

**Domain naming rule**: Derive domain name from business semantics, not directory name. Map directory signals: `users/` + User/Profile models → "User Management"; `competition/` + Competition/Team/Match models → "Competition Management"; etc. When unsure, use the directory name in Title Case as a fallback.

**Cross-cutting detection**: If a directory has no business models, only utility functions/middleware/config, AND is imported by 3+ domains → assign to Cross-Cutting Infrastructure group (one shared node).

**Revised output**: `pending_sections` contains business domain names, not directory names. Each entry records the associated directory paths for reading in Part 3.

### 3.2 — New Part 2a: Architecture Overview Generation (insert after Step 2.3, before Part 2b)

Run once, immediately after `pending_sections` is written.

1. **Step 2a.1 — Draft system diagram**: Create a `flowchart TD` Mermaid diagram where each node is a business domain identified in Step 2.2. Add edges for domains that depend on or call other domains (infer from import topology in Step 2.2 Signal 4).

2. **Step 2a.2 — Draft architecture overview node body**:
   - `## Business Context`: 2–4 sentences from README + project manifest
   - `## Technical Context`: tech stack summary + `### Domains` subsection with one bullet per domain
   - `## Diagrams` with the system diagram from Step 2a.1

3. **Step 2a.3 — Save architecture overview node**:
   - id: `architecture-overview`, title: "Architecture Overview", depth: `core`
   - Write to `.handoff/output/nodes/architecture-overview.md`
   - Add to `index.json` as position 0 entry
   - Print: "✓ Architecture Overview (core)"

### 3.5 — Part 3: Step 3.7 → Step 3.8 Inline Snippets (replaces code_refs)

**Delete Step 3.7** ("Determine `code_refs`").

**Add new Step 3.7** ("Read key source files for inline snippets"):

1. Identify the domain's primary entry point (same heuristic as old Step 3.2)
2. Read: entry-point file, 2–4 files with core business logic
3. For each file read, identify snippets using the priority from research Decision 4:
   - Priority 1: Public API surface — exported functions, class definitions, Django ViewSets/Views, decorators
   - Priority 2: Key business logic methods implementing the domain's core rules
4. Select 1–5 snippets total for the domain (favouring entry-point + most complex logic)
5. For each snippet: record file path, start line, end line, and the literal source lines
6. Apply line limit (5–15 lines per snippet): if a function/class is longer, quote signature + first few lines, add `# ... (lines X–Y omitted)`, quote any clearly important final lines

**Renumber to Step 3.8** or keep as 3.7 — whichever preserves document flow.

### 3.6 — Part 5: Node Assembly Changes

**Step 5.4 — Validation**: Update the validation step to reflect FM-09 is now optional. Remove checks for CR-01 through CR-05 when code_refs is absent. Add check for OP-13 advisory (log but do not fail).

4. Write the complete file to `.handoff/output/index.md`
5. Print: "✓ index.md written"
